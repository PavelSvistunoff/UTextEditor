# UTextEditor

> Актуальний україномовний огляд можливостей. Детальний опис поточної поведінки містить [README.md](README.md), а вимоги й граничні випадки — [SPEC.md](SPEC.md). Цей файл більше не дублює застарілу MVP-специфікацію.

**UTextEditor** — нативний текстовий редактор на Python і PySide6/Qt для окремих текстових файлів та локальних проєктів рукописів. AI на базі Ollama необов’язковий: створення, редагування, пошук і збереження працюють без доступу до моделі.

У налаштуваннях ШІ на вкладці підключення можна задати вікно контексту Ollama в токенах. Типове значення сервера залишає попередню поведінку без перевірки місткості. Явне значення перевіряє заявлену місткість моделі та приблизний бюджет повного запиту з резервом відповіді. Оцінка за байтами UTF-8 не є точним підрахунком токенів; сервер може мати додаткові обмеження пам’яті. Перевищення бюджету спричиняє відмову без автоматичного зменшення вікна.

Перевірка узгодженості не надсилає запит, якщо вибрана сцена, вибрані нотатки та контекст пов’язаних персонажів не вміщаються в ліміт символів або деталі персонажів обмежено. Збільште розмір контексту, виберіть менше нотаток або скоротіть деталі профілів. Підсумок сцени може використовувати позначений уривок. Ліміт символів і вікно в токенах — окремі налаштування. Правила й план RAG описані в [AI context policies and budgets](docs/ai-context-policy.md).

Меню **Проєкт → ШІ проєкту → Індекс пошуку контексту…** відкриває локальне обслуговування індексу: перевірку стану, оновлення, перебудову й видалення кешу. Операції виконуються у фонових потоках і підтримують скасування; вони доступні також із вимкненим ШІ. Кеш містить збережені тексти сцен, нотаток і персонажів та розташований у каталозі `retrieval/` поруч із налаштуваннями програми. Незбережені зміни не потрапляють у дисковий кеш. Пропущені джерела та недоступність SQLite FTS5 явно повідомляються. Індекс використовується для ручних RAG-продовжень тексту.

Команда **ШІ → Переглянути RAG-контекст продовження тексту…** працює для відкритої сцени проєкту. Спочатку задайте явне токенне вікно Ollama й оновіть індекс. Перед надсиланням перегляньте точний запит, роль, бюджет, джерела та повідомлення про неповне покриття. Можна виключити джерела й перебудувати контекст. Діалог показує адресу та модель одержувача. Текст відкритих буферів має пріоритет; зміни джерел скасовують застарілий результат. Недоступний індекс явно позначається й залишає лише обов’язковий контекст сцени. Tab приймає підказку, Esc відхиляє її. Автоматичні та звичайні підказки використовують попередні правила контексту.

У налаштуваннях ШІ можна ввімкнути **гібридний пошук для ручного RAG-продовження тексту**. Адреса й модель векторизації окремі від генерації; типова embedding-модель — `embeddinggemma`, гібридний режим спочатку вимкнений. Перед надсиланням запиту й дозволених уривків, включно з незбереженим текстом, програма окремо підтверджує адресу векторизації. Моделі автоматично не завантажуються. Вектори збережених джерел кешуються локально, незбережених — лише в пам’яті. За недоступності моделі, помилки або понад 512 дозволених фрагментів програма повідомляє про перехід до лексичного пошуку. Подальша генерація потребує окремого перегляду. Видалення кешу також видаляє вектори збережених джерел.

У параметрах автоматичного написання можна окремо ввімкнути **перегляд знайдених уривків перед кожною сценою**. Потрібні явне токенне вікно Ollama та оновлений індекс. Повні обов’язкові нотатки, профілі, записаний розвиток і поточна сцена уточнення зберігаються в запиті. Уривки попередніх сцен можна виключати й перебудовувати до надсилання. Векторизація вмикається окремо та підтверджує адресу. Попередні згенеровані сцени використовуються лише як позначені неприйняті чернетки в пам’яті; подальші тексти можуть залежати від чернеток, які ви потім відхилите. Остаточний перегляд показує перевірені цитати з точного запиту. Частковий пошук не підтверджує узгодженість усього проєкту. Якщо сукупний обсяг записів перегляду перевищує 16 МіБ, жодна чернетка не застосовується.

## Встановлення та запуск

Потрібен Python 3.12 або новіший.

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
python -m pip install -e '.[test]'
python -m app.main
# Або після встановлення:
utexteditor
```

Звичайні офлайн-тести не потребують Ollama:

```bash
QT_QPA_PLATFORM=offscreen PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q
```

Для AI встановіть і запустіть [Ollama](https://ollama.com/). Типові налаштування: `http://localhost:11434` та `gemma4:12b`. Адресу й модель можна змінити; **віддалений сервер отримуватиме надісланий текст**. Окремий хмарний провайдер не налаштований.

## Робота з текстом

- Окремі UTF-8 файли відкриваються у вкладках із незалежним текстом, виділенням, Undo/Redo і позначками незбережених змін. Є New, Open, Save, Save As, Close і підтвердження під час закриття. Історії нещодавніх файлів і проєктів окремі.
- Читання й запис виконуються фоновими задачами. Перед збереженням редактор перевіряє стан на диску; File > Review External Changes показує збережену основу, диск і буфер, пропонує перезавантаження, злиття або інший шлях.
- Пошук і заміна підтримують наступний/попередній збіг, лічильник, необов’язкову нечутливість до регістру й пошук цілих слів. Replace All — одна операція Undo.
- Доступні зміна регістру, відступи, прибирання кінцевих пробілів і форматування абзаців «Як у книжці», а також режим без відволікань.
- Рядок стану показує UTF-8, тип кінців рядків, рядок/колонку курсора й AI-стан. Вибір альтернативного кодування та кінців рядків у UI ще не реалізовано.

## Проєкти рукописів

- Локальні проєкти мають YAML-маніфест `utexteditor.yaml` формату версії 1, стабільні ID, розділи, сцени й окремі довідкові нотатки у звичайних UTF-8 файлах.
- Дерево проєкту підтримує створення, імпорт, перейменування, переміщення, дублювання, видалення, зв’язки нотаток, підрахунок слів і перехід до поточного документа.
- Search > Search Project Text шукає у сценах і нотатках, ураховуючи відкриті незбережені буфери; результати перевіряються на застарілість. Search > Quick Open знаходить сцени, розділи, нотатки, персонажів та псевдоніми. View > Navigation Back/Forward зберігає обмежену історію переходів поточної сесії.
- Профілі персонажів містять біографію, риси, мотивації, пріоритетні цілі, знання, сюжетну арку, спрямовані стосунки, портрети PNG/JPEG та прив’язки до сцен зі змінами стану. Перехід до пов’язаної сцени зберігає незастосовані зміни профілю.
- Локальні знімки відновлення захищають незбережені буфери; під час запуску доступні перегляд, порівняння, вибір відновлюваної копії та відкладання рішення. Оригінальні файли не перезаписуються непомітно.
- Іменовані знімки редакцій можна переглядати, порівнювати та видаляти після підтвердження. Відновлення редакції, автоматичний розклад і політики зберігання ще не реалізовані.

## Інструменти письменника

- Щоденні цілі відстежують слова документа/проєкту або нові слова з урахуванням Undo/Redo. Writing > Writing Goal History показує збережену приблизну історію за локальними датами й дозволяє очистити прогрес без зміни рукопису.
- Експорт у Markdown або текст підтримує вибір сцен, заголовки, розділювачі, незбережені буфери та необов’язковий попередній перегляд захопленої версії.
- Компіляція книжки в PDF підтримує A5/A4/Letter, назву, автора, вибір сцен та показ заголовків. Довідкові нотатки не входять до рукопису.
- View > Markdown Preview відображає поточний буфер без зовнішніх ресурсів; великі документи показуються лише до явно позначеної межі у 65 536 одиниць тексту Qt.

## AI та контроль автора

- Автоматичні inline-підказки можуть окремо використовувати RAG: увімкніть пошук контексту в AI Settings, залиште автоматичний контекст проєкту та явно задайте вікно токенів Ollama. Індекс потрібно оновити заздалегідь. Під час набору індекс і вектори документів не перебудовуються; hybrid потребує окремого дозволу на query embeddings. AI > Inspect Inline Retrieval Context показує точний контекст підказки та дозволяє виключати джерела для наступних запитів. Tab перевіряє джерела у фоновому worker перед вставкою; Esc відхиляє, Undo скасовує прийнятий текст. Для окремого документа без проєкту залишається звичайне автодоповнення. [Межі й вимірювання](docs/rag-inline-retrieval.md).
- Перед першим надсиланням текстового контексту показується **адреса Ollama та категорії даних** і запитується згода. Дозвіл зберігається для конкретної адреси; зміна сервера вимагає нового підтвердження.
- Автодоповнення з’являється як ghost text лише там, де його можна безпечно цілком показати; `Tab` приймає, `Esc` відхиляє. Зміна документа, курсора, налаштувань або контексту робить стару пропозицію нечинною.
- Перевірка правопису й граматики показує перевірені рекомендації. Виправлення застосовуються лише за дією користувача; пакетний перегляд підтримує вибір та одну дію Undo.
- Генерація за запитом, попередній перегляд контексту, необов’язковий потоковий попередній перегляд, допомога персонажам, AI-планування, Auto-pilot, Auto-writer, перевірка узгодженості та переклад проєкту працюють через фонові задачі, перевірки контексту і явний перегляд перед застосуванням.
- Переклад проєкту охоплює також усі заповнені текстові поля персонажів: імена, псевдоніми, мотивації, цілі, знання, минуле, характер, розвиток, описи стосунків і нотатки про участь у сценах. ID, службові категорії та стани, числові значення й портрети зберігаються. Усі зміни видно в порівнянні перед спільним застосуванням.
- Під час заповнення порожніх полів персонажа AI отримує явну мову English або Ukrainian. Вибрана мова письма має пріоритет; у режимі Auto мова визначається за текстом профілю, а за невизначеності використовується активна мова інтерфейсу. Службові ключі та коди не перекладаються; пропозиції потрібно переглянути перед застосуванням. Відомі однозначні помилки формату AI виправляються перед переглядом; повторені однакові ключі арки об’єднують усі запропоновані значення через крапку з комою для перегляду автором, без перезаписування. Невідомі ключі та конфлікти між канонічним ключем і його псевдонімом відхиляються.
- Auto-writer пропонує вибирати чернетки окремих сцен перед спільним застосуванням; переклад проєкту показує порівняння оригіналу та результату, а застосовується цілісно. Скасування чи застарілий стан не повинні змінювати рукопис.
- Мова інтерфейсу: системна, English або Українська. Перемикання діє після перезапуску; неперекладені елементи ще можуть відображатися англійською. Мова інтерфейсу не змінює текст документів чи промпти.

## Обмеження та безпека даних

- **Важливо:** захист від конфліктів запису координує потоки в одному процесі, але **не гарантує**, що незалежна програма не змінить файл після останньої перевірки та перед заміною. [Деталі](docs/save-coordination.md).
- Файли читаються повністю в пам’ять; дуже великі можуть створювати високе навантаження. Підтримується UTF-8 і часткове виявлення двійкових даних, але не всі кодування чи формати.
- Метадані лічильника нових слів можуть зростати зі збільшенням кількості доступних команд Undo.
- Повна діагностика пошкодженого відновлення, нативний аудит доступності й остаточна локалізація інтерфейсу ще не завершені. Знімки відновлення не замінюють резервне копіювання.

Повний контекст для Auto-writer включає всі довідкові нотатки, текстові профілі

відмову від обрізання й мати достатнє контекстне вікно; застосунок не збільшує
його автоматично.
